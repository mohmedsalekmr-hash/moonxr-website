# دليل الطوارئ — موقع Moon XR

هذا الدليل لك أنت، دون الحاجة إلى معرفة البرمجة. اقرأ الحالة التي تشبه مشكلتك، ونفّذ الخطوات بالترتيب.

---

## أين يوجد كل شيء؟

| الشيء | المكان |
|---|---|
| الموقع | https://moonxr-site.vercel.app |
| لوحة التحكم | https://moonxr-site.vercel.app/admin |
| الاستضافة (Vercel) | https://vercel.com ← المشروع `moonxr-site` |
| قاعدة البيانات والصور (Supabase) | https://supabase.com/dashboard ← المشروع `jhferwtmaklnnruorkeh` |
| الكود والنسخ الاحتياطية (GitHub) | https://github.com/mohmedsalekmr-hash/moonxr-website |

النسخ الاحتياطية في الفرع `backups` على GitHub: نسخة من قاعدة البيانات كل ليلة (آخر 30 ليلة)، وكل الصور والفيديوهات.

> ⚠️ نسخة قاعدة البيانات مشفّرة بكلمة سر اسمها `BACKUP_PASSPHRASE`. GitHub لا يسمح بقراءتها بعد حفظها. **احتفظ بنسخة منها في مكان آمن خاص بك** (مدير كلمات السر مثلاً)، وإلا لا يمكن فتح النسخ الاحتياطية.

---

## 1. الموقع لا يفتح، أو يظهر خطأ بعد تحديث جديد

هذا أسهل حالة: نعود إلى النسخة السابقة التي كانت تعمل.

1. افتح https://vercel.com ← المشروع `moonxr-site` ← **Deployments**.
2. ستجد قائمة بكل النسخ المنشورة، الأحدث في الأعلى.
3. اختر آخر نسخة كانت تعمل (التي قبل التحديث)، اضغط على النقاط الثلاث `⋯` ← **Promote to Production** (أو **Instant Rollback**).
4. انتظر دقيقة، ثم افتح الموقع.

لا يضيع أي محتوى بهذه الخطوة: المحتوى (النصوص، المشاريع، الصور) محفوظ في قاعدة البيانات، وليس في النسخة.

## 2. محتوى خاطئ أو محذوف بالخطأ (نص، مشروع، شعار)

1. ادخل إلى لوحة التحكم ← **السجل**.
2. ابحث عن التعديل، واضغط **استرجاع هذه النسخة**.

السجل يحتفظ بكل نسخة سابقة لمدة 90 يوماً.

## 3. الموقع يفتح، لكن المحتوى قديم أو التعديلات لا تظهر

الموقع يحفظ الصفحات لمدة ساعة لتكون أسرع. التعديل من لوحة التحكم ينشر فوراً عادةً. إذا لم يظهر:

1. انتظر دقيقتين وحدّث الصفحة.
2. إن بقي قديماً، اعدّل أي شيء صغير في لوحة التحكم واحفظه، فهذا يعيد نشر كل الصفحات.

## 4. قاعدة البيانات متوقفة (Supabase)

علامة ذلك: الموقع يعمل لكن لوحة التحكم لا تفتح، أو يظهر في Supabase أن المشروع **Paused**.

- الموقع نفسه **لا يسقط** في هذه الحالة: إذا لم تجب قاعدة البيانات خلال 4 ثوانٍ، يعرض الموقع المحتوى المكتوب في الكود.
- لإعادة التشغيل: https://supabase.com/dashboard ← المشروع ← زر **Restore / Resume**.

عادةً لا يحدث هذا: زيارة آلية يومية تُبقي قاعدة البيانات مستيقظة.

## 5. ضاعت بيانات قاعدة البيانات

استرجاعها من النسخة الليلية يحتاج بعض الأوامر التقنية، والخطوات مكتوبة في ملف `README.md` في الفرع `backups` على GitHub. أعطِ هذا الملف لـ Claude أو لأي مبرمج، مع كلمة السر `BACKUP_PASSPHRASE`.

## 6. لا أستطيع الدخول إلى لوحة التحكم

- **نسيت كلمة السر:** في Supabase ← **Authentication** ← **Users** ← اختر حسابك ← **Send password recovery**.
- **إضافة مدير جديد:** يتم الآن عبر Claude أو مبرمج (إضافة الحساب إلى جدول `admins`).

## كيف أعرف أن هناك مشكلة؟

- **فحص كل ساعة:** GitHub يفتح أهم صفحات الموقع كل ساعة. إذا فشل، يصلك بريد من GitHub بعنوان فيه **Uptime check failed**.
- **فحص كل تعديل في الكود:** كل تغيير يُرفع إلى GitHub يُفحص آلياً: كل صفحة على الحاسوب والهاتف. علامة ✓ خضراء بجانب التعديل في GitHub تعني أنه سليم، و✗ حمراء تعني **لا تنشره**.

## عند طلب المساعدة (من Claude أو مبرمج)

أرسل:
1. ماذا حدث، ومتى، وعلى أي صفحة.
2. صورة شاشة للخطأ.
3. هل حدث بعد تعديل معيّن؟

الموقع مبني بتقنيات منتشرة (Next.js، Vercel، Supabase)، فأي مبرمج Next.js يستطيع فهمه. الشرح التقني في ملف `README.md` في الصفحة الرئيسية للمشروع على GitHub.
